# venture_toolkit — 案例工具箱

> 状态：🟢 | 从案例1 泛化的开案-上架-记账模式

## 三件套

1. **intake 流程**：复制 ventures/_template/ → 填四必填（假设/止损线/最小验证预算/点子来源）→ cockpit/status.md 挂灯 → 若属开新线（L3）先写 grill-record
2. **上架物料模式**：listing-{渠道}.md（标题/一句话简介/描述/定价 rationale/冷启动分发/风险注意）+ 交付物 build 脚本模式（案例1 的 dist/ 流程）
3. **记账复盘模式**：案例 ledger.md（日期/事件/金额/渠道必填）+ 周五蒸馏动作（≥1 条 knowledge 或记"无可蒸馏"）

## 上架前质检模式（卖"Audit"类产品的通用打法）

埋雷实测：给产品主张配针对性场景与对照组，保留输入、提示词、模型、输出和判定。**输出不是自动的通过证据**；营销只能使用人工复核支持的结论，模拟场景不能冒充亲历。案例1旧QA报告存在误判，按修订报告处理；真实API复测可能付费，须先授权。

## 离线记录守卫（两条业务线共用）

`python capabilities/venture_toolkit/validate_records.py`：只读检查cockpit行动编号、负责人、状态、日期、证据及剪映观察快照的作品关联、时间、数字和缺失口径。不联网、不改账、不据此自动认定成交或调整L3决策。

净贡献已对账后才可调用`subscription_covered`比较同月固定成本；输入缺失返回未知，¥100不能覆盖¥118。业务状态见cockpit/status，结构测试通过不等于真实经营流程通过。
