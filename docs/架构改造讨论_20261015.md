## 一、本地项目借鉴清单（比外部资料更有价值——它们在生产环境跑着）

### 来自 fulu-odps-data-bridge（AI 辅助数据开发平台）

| 模式 | 长什么样 | 搬到本项目的对应物 |
|---|---|---|
| **`.claude/skills/` 能力层** | 20 个 skill（data-development / data-quality-check / health-check / compliance-audit / pre-commit-check / requirement-continuation...），每个是自包含文件夹，`skill-rules.json` 管路由 | **"能力"模块直接用这个形态**——这就是 Agent Skills 标准的实战版，且 BOSS 已有手感 |
| **`metadata/` 知识库** | 中心→业务线骨架→表元数据三级；**"骨架=单一信息源"原则**：白名单只在 business-lines/README.md 一处维护，其他地方只放链接，"避免分散同步漂移" | **"知识库"模块的核心原则**：每个事实只有一个 canonical 位置。防知识库变垃圾堆 |

### 合并外部研究结论

- Voyager 技能库：能力从真实任务中攒出来（Rule of Two），入库前验证过
- Agent Skills 标准 = .claude/skills 形态，Claude 原生识别零成本
- Personal AI OS 四层：Context/Connections/**Capabilities/Cadence**——Cadence（调度）不可缺

## 二、目标架构提案（v0.2 讨论稿）

```

│

├── GLOSSARY.md               # 术语地图：能力/案例/知识/收入口径/完结定义

│   ├── product-launch/       #   上架交付（PDF管线/物料模板/上架runbook模式）

│
├── ventures/                 # 【案例层】一业务线一目录，统一状态机
│   ├── _template/            #   案例模板：brief→research→plan→execute→data→postmortem
│   ├── ai-workflow-kit/      #   案例1：AI资料包线（docs/回本计划+products 迁入）
│   ├── jianying-templates/   #   案例2：剪映模板线（两份调研/计划迁入）
│   └── xhs-account-v1/       #   案例3：小红书账号线（已完结→archive 化封存）
│
├── knowledge/                # 【知识库】从案例蒸馏的跨线知识（单一信息源原则）
│   ├── MEMORY.md + *.md      #   Claude 原生 memory 机制（一事实一文件）
│   ├── grill-records/        #   重大决策拷问记录（DataCenter 模式）
│   └── playbooks/            #   蒸馏出的打法（如"冷启动三渠道分发法"）

├── assets/                   # 【资产登记】账号/Cookie/实名/在售链接/API key 清单+健康检查

└── 98-debt/                  # 技术债与遗留（DataCenter 惯例）
```

### 五条设计铁律

1. **Rule of Two**：能力升级为 capabilities/ 原生成员的条件 = ≥2 个案例真实用过
2. **单一信息源**：事实只在一处 canonical，别处放链接（bridge metadata 原则）
3. **能力带健康检查**：每个 capability 有 status（依赖/Cookie/最近成功运行），像 xianyu 四状态灯
4. **案例带状态机**：idea → researching → planning → executing → selling → maintenance / closed，cockpit/status.md 是唯一状态汇总处
5. **知识必须蒸馏自案例**：knowledge/ 只收跨案例可复用的结论，单案例细节留在 ventures/ 内

### 迁移策略（渐进三步，git rename 保历史）

- **Step 1 骨架**：建新目录 + GLOSSARY + CLAUDE.md 新宪法 + cockpit（合并回本计划）——半天
- **Step 2 迁移**：现有资产按映射表 git mv（docs/调研计划 → ventures/，core/agents → capabilities/content-factory/，scripts 按归属拆）；旧 import 路径同步改；跑测试
- **Step 3 蒸馏**：从三个案例各蒸馏 ≥3 条知识入 knowledge/；写第一份 grill-record（"从账号运营转向孵化台"）
