## 一、这是什么（一段话）

**个人商业孵化台**：通过一条条真实挣钱案例（带止损线的实验）培养"会挣钱的 AI 操盘手"。
BOSS 是委托人+机会传感器（管方向、拍板、承担后果）；AI 是参谋部+执行工厂（调研、生产、
交付、记账）。项目的存在理由：**GLM Coding Plan ¥118/月 由项目自挣**（cockpit/ledger.md 对账），
长期目标：可持续净现金流最大化（宪法，根 CLAUDE.md）。

## 三、运行机制与原理（五条循环）

1. **开场注入（防失忆）**：每次 AI 会话处理业务前必读 status → 活跃案例 venture.md → 相关
   knowledge。AI 每次会话"失忆重启"，这套协议把项目积累重新注入——这是"越用越聪明"的工程本质。
2. **案例状态机**：`idea→researching→planning→executing→selling→maintenance/closed`，
   开案必填止损线+最小验证预算；状态只在周五复盘更新；关单必写 postmortem+蒸馏 ≥1 条知识。
3. **Rule of Two 能力生长**：缺口先住案例 tools/（练习本），第二次被用才上货架（内化为能力）
   ——货架从重复需求里长出来，不从预想里造。
4. **周五复盘（Cadence）**：账本→状态灯→蒸馏→资产健康→下周计划。知识库的粮食绑定在这，
   不绑任何机器（knowledge_base 遗址死因，见 playbooks/03）。
5. **授权分级（L0-L3）**：L0 全自动→L3 必须讨论（开线/砍线/定价/花钱>¥200 永久保留）。
   边界由战绩搬动，记录在 authorization.md——这是"AI 越来越主导"的安全轨道。

**每日心跳**（pulse）：读取[行动回执](../../cockpit/actions.csv)的明确截止日、案例状态及本周焦点，生成“今日三件事+预警”。逾期持续提醒，完成/取消/关闭案例不提醒；不扫描正文日期。实际部署、失败回执及重试契约见[pulse说明](../../capabilities/pulse/README.md)。

2026-10-29本机未查到`incubator_pulse`，当前Qoder自动化列表为空，其他运行环境未知。代码与离线测试完成不等于计划任务已经运行，不以绿色状态掩盖部署缺口。

## 四、使用方式

### BOSS 日常（三分钟上手）

| 场景 | 动作 |
|---|---|
| 每天早上 | 看微信晨报三件事（或读 cockpit/journal/今日.md） |
| 做完了 | 及时把动作结果及遮敏证据回填cockpit/actions.csv；周五集中评审，提交文件不等于商品已上线 |
| 有新点子 | 告诉 AI → 走 intake（复制 _template 填四必填）→ 属开新线则先写 grill-record（L3） |
| 每周五 | ~20 分钟复盘（AI 主导执行五件套流程） |
| 想看战局 | 问 AI"现在怎么样"，或自己开 cockpit/status.md（唯一状态源） |

### AI 会话（接手协议）

开场注入三步（宪法规定）→ 活在授权分级内 → 改动遵守四条行为准则（Think/Simplicity/Surgical/Goal-Driven）→ 产出默认走"案例内实践"路径。

### 常用命令

```bash
pytest                                    # 活能力测试（结构守卫+pulse 等）
python capabilities/pulse/heartbeat.py    # 手动心跳：晨报→journal→微信
python capabilities/xhs_crawler/verify_search.py   # 站内搜索采集
python ventures/ai_workflow_kit/tools/test_workflows.py  # 案例1 质检
# 遗产流水线测试：cd capabilities/xhs_content/legacy-pipeline && python -m pytest
```

### 连接器通道（三选一）

默认复用 xianyu/push.json（serverchan，免费 5 条/天两仓共享）。要专属额度：
在 `.cache/pulse_push.json` 写 `{"provider":"pushplus","key":"你的token"}`（或 wecom 群机器人
webhook key）——存在即优先生效，不动共享配置。

## 五、维护手册

### 心跳不响了，按序排查

1. 只读查询：`schtasks /Query /TN incubator_pulse`。不存在则记录部署缺口，不在诊断时自动安装。
2. 先离线预览：`python capabilities/pulse/heartbeat.py --dry-run`，不推送、不消费额度。
3. 查看`.cache/pulse_last_run.json`及安全日志区分预览、已生成、已推送、失败或送达未知；journal存在不等于通知送达。
4. 真实发送和启用定时须先确认；失败原因按回执排查，不能把一切失败归因于额度，也不假设次日必然恢复。

### Cookie 过期（xhs_crawler）

跑 `python capabilities/xhs_crawler/xhs_auth_helper.py` → 弹二维码大图 → 手机小红书扫码。
详情接口记得带 xsec_token（verify_search.py 已处理）。

### 测试与质量

- 根 `pytest`：现役工具离线回归，具体覆盖以tests及本次运行结果为准；包括记录契约、数值解析、路径、心跳边界和输出安全。遗产测试仍隔离，不用测试数量冒充经营验证。
- lint：`python -m ruff check .`（vendor/legacy/归档案例已排除）

### 常见坑速查（都踩过、都记档）

死系统代理伪装 Cookie 失效｜pip 装包先绕代理｜bat 必须 CRLF+ASCII 内容｜闲鱼机器人连环重启触发
RGV587 风控（冷却+过滑块）｜发布二维码没人扫=白干（Day0 分发铁律）｜小红书站内绝不挂外链。

## 六、迭代演化方向（按 Rule of Two 排序，不预建）

| 优先 | 方向 | 触发条件 |
|---|---|---|
| v1.1 | 连接器专属通道（pushplus/wecom） | 额度挤占常态化的第一周 |
| 进化1.0（历史机制，当前待核验） | 旧CC会话曾记录周五21:07与7天续期 | 不能迁移推定为当前Qoder已安装；当前工具支持独立持久任务，不默认要求自我续建。选择执行位置并获得授权后另作部署验收 |
| **进化2.0** 待批 | 自主观察+自蒸馏：pulse 周跑爬虫(L0)→LLM API 蒸馏草稿→knowledge 待审队列→微信提醒审阅（L1） | **BOSS 拍板**：自主 LLM 调用=自主花钱，属 L3 范畴 |
| v1.2 | 心跳加"晚间收盘"回执 | 双向通道就绪（pushplus 回执或企业微信应用） |
| v1.3 | 心跳自动跑竞品监控（周二/四，L0 只读） | 剪映线进入 selling 且监控成为日常 |
| v2 | cockpit 数据化（md→sqlite+小面板） | 案例数 >10 或流水过百笔 |
| v2 | 任务总线/提案队列落码 | ≥2 个案例同时有 L2 待办队列 |
| v3 | LLM 个性化晨报（确定性规则之上） | 心跳稳定运行 4 周 |
| 远期 | B 端供货自动化、第二曲线（micro-SaaS）、仓库改名 | 案例验证通过后 |

**不变的三条底线**：发布永远人工触发（合规红线）；L3 永久归 BOSS；一切新机制从案例需求里长。
