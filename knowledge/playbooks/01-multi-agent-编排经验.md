# Playbook 01 — Multi-Agent 编排经验（源自案例3 流水线，2026-10 蒸馏）

> 最后验证：2026-09（案例3 运行期）。适用场景：任何"多角色协作的自动化生产系统"（内容/交付/审核）。

## 有效的设计（复用清单）

1. **发布/订阅总线优于点对点**：9 种消息类型 + 广播/定向双模式，加角色不动主干（MessageBus 模式）
2. **审核循环必须带熔断**：A 级过/B 级 issues≤2 过/**连续 3 轮同级强制通过/上限 5 轮放弃**——没有熔断的审核循环会死循环烧钱
3. **Agent 记忆按 Agent 分文件**：成功/失败模式分记，think() 时自动注入（AgentMemory 模式）
4. **凡 prompt 写了但 LLM 不稳定遵守的规则，一律代码兜底**（标签净化、健康检查皆实例）——这条是全项目最硬的工程教训
5. **并行要在"知道总量"之后**：先算分页拿准确页数，再开线程池渲染（先计划后并行的通式）

## 无效的设计（避免清单）

1. 流水线再精美，**分发动作不发生=零**——案例3 全套 7-Agent 系统败于此，不是败于质量
2. 预设评论类"拟人自动化"撞平台治理（2026 严打），预设内容默认禁用是对的
3. 为单一案例建造重型基础设施时机过早——这套系统的正确诞生时机应是"第二个内容案例出现之后"（Rule of Two 的又一佐证）
