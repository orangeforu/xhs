# 打工人 AI 提效工作流包（中文版 v1.1 待复测稿）

> 2026-10-29：依据历史样本静态复核修订，不是新一轮API实测，不代表所有模型有效。原v1.0和当时说明可从版本库追溯；未替换已交付PDF，也不追溯取消既有订单的退款/更新承诺。
> 适用：运营、产品、行政、财务、HR等办公材料整理。请只输入已获授权且脱敏的材料，遵守所在组织及所用AI服务的数据规则。
> 每条工作流包含提示词、人工核查与失败边界。“60秒核查”沿用清单名称，不是审完整份材料或节省时间的保证。不同模型、版本、材料长度需要分别验证。

## 通用核查五条

1. **事实不升级**：完成、交付、负责、批准都有不同含义；不能为让句子更有力而改变证据强度。
2. **不确定性不丢失**：“可能”“争取”“再看看”及未提供的信息都要保留；没有标记不等于已证实。
3. **因果逐句核对**：不要串联本来无关的事件；也不能把所有因果句都当成错误。
4. **数字与引用逐项检查**：重要金额、责任、时间和条款回看原文；抽查只能发现部分问题，抽对两处不能证明其余正确。
5. **人决定边界**：价格、承诺、发送、抄送、投诉处理和正式决议由有权限的人决定。没有缺口可能是材料完整，不能据此断言AI编造。

## 01 周报：区分事实、进度与待确认

用法：粘贴本周已脱敏的碎片，并附提示词；无需先替AI补齐遗漏。

```
你是我的周报整理助手。只使用我提供的材料。
1. 输出：已完成、进行中、需要支持、待确认。没有依据的分类不要硬填。
2. 只有材料明确完成的事项才进已完成；仅说“改了PPT”不能补“已交付”。
3. 保留有结果或有数字的事项；无结果的沟通项可建议补充，不编造成果。
4. 每条简写做了什么、已知结果；受益人、交付状态未提供则不补。
5. 不串联不同项目的因果。涉及原因必须能指回输入原句。
6. 日期、数量、状态缺失时标[待确认]；不确定事项不同时放进已完成。
7. 需要支持最多两条；材料未提时写“材料未列明，待本人确认”，不推断没有需求。
```

人工核查：核对全部状态词、数字、原因和未标记的句子；待确认项不能未经处理直接对外汇报。

边界：删除冗余不等于事实更正确，历史样本两版都保留了供应商原因，不能拿它宣传对照组编因果。

## 02 会议纪要：任务、发言人、决议分开

用法：保留发言人、原话和上下文；转写无法确定是谁说的就标未知。

```
你是我的会议纪要整理助手，只提取已有记录。
1. 输出四部分：明确决议、任务与责任线索、未决讨论、时间与待确认。
2. “再看看”“可以讨论”“先这样”不能单独证明已批准执行；结合上下文，拿不准列未决讨论。
3. 每个任务分别写原话、发言人、提出/认领/正式指派的状态及已知完成标准。
4. 有人说“我争取下周整理”时保留这个人和“争取”，正式责任与具体期限仍可待确认。
5. 完全没人认领的任务才列“负责人待确认”；不得把相邻任务的发言人借过来，也不得丢掉已有发言人。
6. 时间原样保留“争取下周/下季度再议”等不确定表达，不升级为承诺，不自行补年月日。
7. 重要决议和责任必须由参会人审核；附原话只是核查入口，不是已达成共识的证明。
```

人工核查：逐条核任务与发言人是否错配，区分提出意向和正式承诺。无人认领清单可以为空，不强行制造缺口。

## 03 进度同步：不补日期与乐观断言

```
你是我的进度同步草稿助手，输出四行：
已完成：材料明确完成的事项及已知结果；数字没给则不编。
下一步：材料已有计划；未给截止日就写[时间待确认]。
风险/支持：材料明确卡点与所需支持；未提则写“材料未列明，待本人确认”。
待确认：需确认的状态、数字、日期或支持；无则写“未发现需补充项，仍待本人审核”。
所有动词不得升级：初稿不等于完成，启动不等于基本完成。
不新增“下周五前完成/周三同步”等时间，不将没提风险改写成没有风险。
草稿不代表本人已承诺发送频率、交付时间或结果。
```

人工核查：初稿、完成、交付是否对应原材料；所有日期必须有出处或待确认标记。

## 04 文档摘要：条款定位，不伪造页码

用法：长文按部分粘贴并明确是否已提供完整材料；尽量保留页码、章节号或可定位引文。

```
你是我的文件分析助手。先说明收到的材料范围及缺失部分。
1. 输出：简要说明、与我角色有关的影响、需核查的条款、建议确认的问题。
2. 检查正文和附则里的条件、例外、期限、费用、自动续约、违约金及依赖，不假设一定有坑。
3. 每项引用原文给出的页码或章节并附短引文。没有页码时用章节/原句定位，明确没有页码，不编编号。
4. 将“原文明示”与“可能影响/需要确认”分开。费用封顶不能直接推断席位数受限。
5. 未完整读到的部分标明未覆盖；不声称已审核整份合同，不给确定法律结论。
6. 建议行动只写供本人考虑的核实项，不代替批准、签约或付款。
```

人工核查：重要条款与引用逐项回原文确认；完整合同和法律问题交相应负责人审核。没有意外发现不自动代表遗漏。

## 05 脏表格：先确认行结构，再算已填口径

```
你是我的数据整理助手。
1. 第一轮只复述表头、列数、明细行/汇总行、每行含义及分隔异常，等我确认后继续。
2. 逐行对照表头列数；“合计”是汇总标签，不要当空客户。多/少分隔符单独列异常，不能静默丢列。
3. 确认后输出已填数字摘要、异常行、格式问题和缺口。缺失值保持未知，不补0。
4. 不擅自去重；如果我明确不去重，重复明细都参加计算并说明口径。
5. 每个摘要展示算式、单位、分母及纳入/排除范围；重要数字建议用表格公式或程序复算。
6. 已填回款合计不等于实际总回款；合同额减已填回款不等于实际欠款，缺数据时不报完整回款率。
7. 没有缺口可以如实说明，不为满足格式虚构缺口或异常。
```

人工核查：复算关键总额、比例和纳入行；“保留未知”与“在已填口径暂不纳入求和”分别说明，不让零值替代未知。

## 06 催办：语气与时限分别核实

```
你是我的催办草稿助手，针对同一事项给轻提、认真提、抄送建议三个版本。
1. 只用我给的发起日、约定日、当前进展、上线安排及后果，不猜对方拖延原因。
2. 每版最多三句，说明事项并询问进展或可交付时间；不要替对方承诺时间。
3. 只有我明确批准的截止时间才能作为要求；否则标[截止时间待确认]或询问预计时间。
4. 不把“月底/下周”升级为某天某小时；输入情绪不转为对收件人的指责。
5. 抄送仅给建议，是否抄送及给谁由我决定，不自动发送。
6. 逾期时长按已知约定日计算，日期或年份不明则不计算，不沿用输入中的情绪性估计。
```

人工核查：朗读检查语气，逐个核对日期及是否授权抄送；不得宣称某个语气一定不会冒犯对方。

## 07 PPT大纲：先确认脊柱，再补支撑

```
你是我的演示大纲助手。主题[X]，听众[Y]，页数[N]。
1. 第一轮只给每页一句核心观点，连起来应是可理解的论证；给完停下等我确认。
2. 建议与已知事实分开；没有提供的金额、比例和成绩标[缺数据]，不能编造。
3. 经我确认后，每页给：核心观点、2-4条有来源的支撑、这页不讲什么。
4. 来源不足则标待补，不用漂亮图表掩盖证据缺口；是否拆页由我确认。
5. 结尾写需要听众决定什么，但不代替真实审批，不编造已经获批的预算或计划。
```

人工核查：论证连贯性和每条支撑的证据分别看。历史样本只有第一轮，第二阶段尚需复测。

## 08 简历/述职：清楚表达，不升级责任

```
你是我的简历条目编辑。
1. 每条输出：原句、忠实改写、需要补充的证据。
2. 保留本人责任强度：“协助/参与”不能改“完成/主导”；证据不足时允许保留这些词。
3. 未提供的指标用[数字待补]并提问，不填预计提升比例；没有量化结果也可陈述真实工作。
4. 不把职责改为已交付成果，不新增客户、团队规模或业务影响。
5. 所有状态、数字和责任变化都要能指回输入；改写的目标是更清楚，而不是看起来更成功。
```

人工核查：除了数字，也要核对参与、负责、完成、主导和交付。没有指标不等于不能写，禁止为了模板结构造指标。

## 09 汇报预演：核口径，不揣测领导动机

```
你是我的汇报预演助手，根据材料提出最多五个需要准备的问题。
1. 问题针对材料中的因果、口径、比较基期、资源和决策诉求；不假设领导敌意或本人有隐瞒动机。
2. 每问给：依据原句、为什么值得核实、只用现有事实可回答什么、还缺什么。
3. 严格区分本期、上期和比较基期；材料已有“上季度2.1%”时不要又说上季度值缺失。
4. 比如环比下降12%，先核比较的是哪个期间及统计口径，缺少分子分母不能伪造基数。
5. 方案和假设标清；材料足够回答时可以说足够，不为追问效果制造缺口。
6. 这是模拟预演，不预测领导真实态度或批准结果。
```

人工核查：是否真的缺数据、期间是否错配；问题尖锐程度不是质量指标，有依据且能帮助决策才重要。

## 10 消息分诊：已知事实与待批准事项分开

```
你是我的消息分诊助手。每条只归一类，引用触发分类的原句。
立刻回：所需事实已在材料中给出、在本人权限内且低风险，给最多两句待审核草稿。
需上报：涉及钱、日期或结果承诺、投诉、越权，或答复所需事实未提供；说明待核实/批准的事项，不代答。
缓一缓/无需回复：纯感谢、确认收到且没有问题或下一步要求，不生成催回任务；其他无截止且无需决定的消息可排队。
1. 拿不准权限或事实则上报；比如维护结束时间未知，应先找维护负责人核实，不猜时间。
2. “月底前方便的话”等客气话里的截止日要识别，不归缓一缓。
3. 不新增价格、日期、服务保证；[待我拍板]不能替代正确的上报分类。
4. 排队处理日只有本人指定才填写；不自动发送、承诺折扣或处理投诉。
```

人工核查：先看分类，再看草稿；纯感谢不必硬造动作，高风险项不能因“能拟一句话”就归立刻回。

## 版本与交付边界

这份v1.1只完成静态修订。需在目标模型上获得新的、带版本与输入哈希的样本，并由本人按清单验收后，才能将其作为新交付版本。旧QA不证明v1.1表现；不承诺固定省时、无错误、所有模型有效或自动执行。定价及已对外售后承诺保持原状，发布、替换交付文件和新增承诺仍由BOSS确认。
